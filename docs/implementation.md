# 実装メモ

## 盤面表現

現行ソルバーは `N <= 64` を対象とする。32bit版の `solve_memo` と64bit版の `solve_memo64` を分けている。

盤面は黒石・白石それぞれの bitboard で表す。

```cpp
using Board32 = std::uint32_t; // solve_memo
using Board64 = std::uint64_t; // solve_memo64

Board black; // 黒石がある位置の bit が 1
Board white; // 白石がある位置の bit が 1
```

位置 `i` は左から `i` 番目、つまり bit `i` に対応する。

関連する共通処理は `src/bitboard.hpp` に置いている。

## 合法手生成

合法手は次の和集合として生成する。

```text
合法手 = 捕獲手 ∪ 非自殺手
```

捕獲手は、相手の連の呼吸点が 1 つだけであるとき、その唯一の呼吸点である。

非自殺手は、着手後に自分の新しい連が少なくとも 1 つの呼吸点を持つ手である。一次元盤面では、次のどちらかを満たす空点になる。

- 着手点の隣に空点がある。
- 着手点が自分の連に接しており、その連が着手点以外にも呼吸点を持つ。

この処理は `src/bitboard.hpp` にまとめている。連の列挙ではなく固定回数のシフト伝播で、左右の呼吸点が同じ連に接続しているかを判定している。

## 探索

`solve_memo` と `solve_memo64` は negamax 型の勝敗探索を行う。

- 捕獲手が存在する局面は即勝ち。
- 合法手が存在しない局面は負け。
- それ以外では、子局面に負け局面があれば勝ち。

初手は左右対称性を使い、左半分だけを計算して反対側へコピーする。

### 相手の即捕獲手を生む手の枝刈り

一次元盤面では、相手の連の隣に置く非捕獲手は、次の相手番で捕獲される。

手番プレイヤーの着手点を `x` とする。`x` が相手の連の隣にあり、その手が捕獲手でないなら、相手の連には `x` 以外の呼吸点が少なくとも 1 つ残る。

一方、`x` に置かれた自分の新しい連は、相手の連がある側を塞がれている。一次元盤面で連の呼吸点になり得るのは左右端の隣だけなので、この手が合法な非自殺手であるためには、反対側に呼吸点を持つ必要がある。したがって、その新しい自分の連は呼吸点を 1 つだけ持つ。

次の相手番では、相手はその唯一の呼吸点に着手できる。この着手は自分の連の呼吸点を 0 にする捕獲手なので、相手が即勝利する。

そのため、現在の局面に自分の捕獲手がない場合、着手後に相手の捕獲手が存在する候補手は、勝ち手になり得ない。メモ化つきソルバーはこのような手を再帰探索に渡さずに捨てる。

### 証明済み初手の即時判定

初手については、証明済みの事実を使って探索前に勝敗を返す。

- 端は負け。
- `N >= 5` の近端は負け。
- 初手後の `A(a,b)` が `A(n,n)` または `A(n,n+1)` なら勝ち。
- 初手後の `A(a,b)` が `A(a,a+2)` なら負け。

これは初手候補を直接判定するだけなので、局面ごとの追加コストはない。

### 証明済み gap 族による再帰中の即時判定

`solve_memo` と `solve_memo64` は、探索中の局面を現在手番から見た gap の
多重集合へ分解し、証明済みの族に一致する場合は再帰探索せずに勝敗を返せる。
実装は `src/proof_rules.hpp` に分離している。

即時負けとして使うのは次の有限直和である。

```text
T0..T8 の有限直和
A(n,n), A(n,n+1)
R(a)=MO(1)+WM(a)+WO(a)
```

これらは、それぞれの成分の中で応手が閉じ、2 手後に同じ種類のより小さい
成分または 9 族の有限直和へ落ちることが証明済みである。そのため、複数の
証明済み負け成分の直和も安全に負けとして扱える。

また、現在手番が合法手を持たない不活性成分は、証明済み負け和に加えても
負けである。現在手番は不活性成分に打てず、応手側が証明済み負け和の側で
応手すれば、2 手後に不活性成分の相対境界は元に戻るためである。

即時勝ちとして使うのは、局面全体が次の 2-gap 型に一致する場合だけである。

```text
A(1,b)  (b >= 3)
A(a,a+2)
```

勝ち局面は負け局面と違い、任意の直和で閉じるとは限らない。したがって、
これらは局面全体が完全に一致した場合にのみ使う。

この再帰中の判定は、局面ごとの gap 分解コストがあるためデフォルトでは無効である。
有効化して比較する場合は次を指定する。

```text
--proof-rules
```

`A(2,b)`, `H0/H1`, `K0/K1` など、まだ観測段階の補助族はここには含めない。
`Q0/Q1/Q2` のような不活性成分付きの候補族も同様に、証明が完了するまで
探索本体の枝刈りには使わない。

## メモ化

疎メモ化では、黒石と白石が隣接しない局面だけを対象にした rank key に変換して保存する。

通常探索でメモ化する局面では、黒石と白石は隣接しない。黒白の接触を生む非捕獲手は、次の相手番の即捕獲勝ちを許すため、再帰探索に渡されない。捕獲手が存在する局面も即勝ちとして扱うため、その先の終局状態はメモ化しない。

rank key は、各マスの状態を次の三値として左から順に見たとき、黒白が隣接しない列だけを辞書順に数えて作る。

```text
0 = 空点
1 = 黒石
2 = 白石
```

`N <= 32` で黒白が隣接しない列は最大でも `2140758220993 < 2^41` 個である。勝敗値 2bit を足しても 43bit で足りるため、32bit版は 1 entry を 6 bytes に詰めている。

`N <= 64` では rank key が 64bit に収まらないため、64bit版は `unsigned __int128` で key を扱う。黒白が隣接しない64マス列は 128bit には収まり、勝敗値 2bit と合わせて 1 entry を 11 bytes に詰めている。

```text
entry = (contact_free_rank << 2) | value

value:
0 = empty entry
1 = losing position
2 = winning position
```

rank key は 8 マス単位の事前計算テーブルで変換する。

メモテーブル実装は `src/memo_table.hpp` に分離している。

## ファイル構成

- `src/solve_memo.cpp`: コマンドライン引数の処理と実行制御
- `src/solve_memo64.cpp`: 64bit版のコマンドライン引数の処理と実行制御
- `src/solver.hpp`: メモ化つき探索本体
- `src/solver64.hpp`: 64bit版のメモ化つき探索本体
- `src/ranker.hpp`: dense memo 用の状態数計算と rank 計算
- `src/memo_table.hpp`: dense/sparse メモテーブル
- `src/pattern_evaluator.hpp`: ムーブオーダリング用の5マス窓評価
- `src/bitboard.hpp`: bitboard による合法手生成と盤面操作
- `src/solve_simple.cpp`: 小さい盤面用の参照ソルバー

関連する理論メモとして、空き区間への分解と部分ゲーム化の方針を [gap_game.md](gap_game.md) にまとめている。

## ムーブオーダリング

候補手は次の優先順位で並べる。

1. 5 マス窓パターン評価が高い手
2. 相手の合法手数が少ない手
3. 左側の手

5 マス窓評価は探索結果に基づくオンライン更新で重みを調整する。これは手順の順序付けだけに使い、勝敗判定の厳密性には影響しない。
